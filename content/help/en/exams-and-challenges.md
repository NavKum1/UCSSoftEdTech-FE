Everything here is graded, and passing earns a credential: a signed record anyone can check. These are under [ui: Prove your skills] in the [ui: Practice] menu.

## Written exams

Open [ui: Written exams]. [ui: Available exams] lists the exams you can take. Each card shows how long it takes, how many questions it has, and how many tries you have left.

- **Credential exams** ([ui: Credential exam: answers not shown]) can earn a credential. You get a few tries, with a wait between them.
- **Practice exams** don't give a credential. Many show the right answers after you submit; the card says so.

1. Select [ui: Start exam], or [ui: Start practice exam]. The clock starts.
2. Answer each question. Move with [ui: Next question] and [ui: Previous question].
3. Select [ui: Submit final exam] before the time runs out. If the time runs out first, the try isn't graded, but it still counts as one of your tries.

You see your score, the [ui: Passing score] and whether you passed. Passed a credential exam? Select [ui: Claim verified credential] to add it to your credentials and your skill passport. To try again, select [ui: Retake exam]. Your past tries are under [ui: My attempts and credentials].

### Your own practice exams

- [ui: Generate an exam with AI]: choose a [ui: Topic], [ui: Difficulty] and [ui: Number of questions], then select [ui: Generate and start].
- [ui: Import questions]: add your own questions. Select [ui: Load an example] to see how to write them, then [ui: Publish questions].

Only you see the exams you make, and they don't give a credential.

## Coding challenges

[ui: Coding challenges] opens a practice editor where nothing is graded. Use [ui: Run code] to try things out.

For the real thing, pick a challenge from [ui: Graded challenges]. Challenges marked [ui: Pro] need the Pro plan; see [Pricing and minutes](/pricing). Each challenge has four steps:

1. **Write or fix the code** in your browser. Some challenges are an existing project with defects to find and fix. Select [ui: Run] to try your code, then [ui: Submit Sprint].
2. **Tests:** hidden tests check your code.
3. **Voice defense:** a short spoken conversation with an AI interviewer about your code: why you made your choices, and what you'd change. Select [ui: Start defense], and [ui: End call] when it's over. If voice doesn't work for you, select [ui: Answer in writing instead].
4. **Result:** if you pass, you get a credential. Sometimes a reviewer confirms it first; until then it shows as under review.

> Your edits, pastes and switching away from the window are recorded, and reviewers see them with your work. The challenge also says whether AI tools are allowed: [ui: No AI tools], [ui: AI use reviewed] or [ui: AI allowed].

Your work is saved as you go. If you lose your connection, come back and pick up where you left off. Each result, with its feedback, is in [My results](/my/results).

## Defend your GitHub work

[ui: Defend your GitHub work] lets you defend code you really wrote. It works with public projects only.

1. Paste the [ui: Link to the GitHub repository or pull request], add the [ui: Pull request number (optional)], and enter [ui: Your GitHub username].
2. Select [ui: Get verification code].
3. Add the code to your GitHub profile bio, or to the description of a public gist, then select [ui: Verify]. You can remove the code from GitHub afterwards.
4. Edulexa checks how much of the work is yours and picks the files you wrote.
5. Under [ui: 3. Defend it], select [ui: Start defense]. The interviewer asks about those files.

If you pass, a credential for this work is added to your credentials.

> A voice defense uses your voice minutes for the time you talk, rounded up to the next minute. Answering in writing uses none.
